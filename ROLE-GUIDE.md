## Interview rehearsal

Use Java for the currently recorded Java/Spring interview relevance. Reproduce the existing walkthrough before claiming ownership: create a case, replay its idempotency key, reject an altered payload, review with a distinct actor, then explain the transaction and relay failure boundary. The application's test reports support the mechanism; they do not prove the owner has practiced it.

For a 60-second explanation, cover problem, architecture, one invariant, one tested failure and one production limitation. For a three-minute explanation, add the database transaction, concurrent workers, ambiguity between an external effect and acknowledgment, and the separate production acceptance work. Use personal experience details only where independently true.

Do not invent STAR outcomes. Ask yourself which decisions you personally made, what alternatives you considered, what test you can reproduce and what real outcome you can substantiate. Until those answers are established, present a source walkthrough rather than an employment story.

## Recruiter visibility

Java, Nexus and Streaming are private draft sources. The profile candidate can describe them, but a recruiter cannot inspect their code or runs without access. Current public Career Intelligence and WhatsApp sources are supporting prototypes. Profile publication, proof-source sharing/public-safe release and actual pinning are separate unfinished steps.
